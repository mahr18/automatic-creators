# تشغيل MAHER CONTENT BRAIN من الآيفون — للمبتدئ

## 1) ما الذي لديك الآن؟
المستودع هو: mahr18/automatic-creators

يتكون من واجهة هاتف، Brain API، وكلاء للبحث والاستراتيجية والـPrompt والـCritic والإصلاح، ذاكرة مشروع، YouTube adapter اختياري، وVeo adapter اختياري.

## 2) مفتاح OpenAI
في شاشة OpenAI التي ظهر فيها Key ready اضغط Copy key. لا ترسل المفتاح في المحادثة ولا تضعه داخل GitHub. عند إنشاء خدمة Render يوضع فقط في Environment Variables باسم OPENAI_API_KEY. الشاشة نفسها تنبه أن المفتاح لن يمكن استرجاعه لاحقًا.

## 3) مفتاح دخول الموقع
هذا مختلف عن مفتاح OpenAI. أنشئ قيمة عشوائية طويلة مثل MAHER-BRAIN-CHANGE-THIS-TO-A-LONG-RANDOM-VALUE. لا تستخدم المثال نفسه. اسم المتغير هو BRAIN_ACCESS_TOKEN.

## 4) نشر الموقع على Render
Render يدعم حاليًا Free Web Services لتطبيقات Python/FastAPI، ويعطي الخدمة عنوان onrender.com. الخدمة المجانية تدخل في sleep بعد 15 دقيقة من عدم النشاط، والملفات المحلية مؤقتة. راجع قيود Free قبل الاعتماد عليها للإنتاج. 

الخطوات من الآيفون:
1. افتح Render وسجّل الدخول واربط GitHub.
2. اختر New ثم Web Service.
3. اختر مستودع mahr18/automatic-creators.
4. اترك التشغيل عبر Docker لأن المستودع يحتوي Dockerfile.
5. اختر Free أثناء التجربة.
6. أنشئ الخدمة وانتظر البناء.

## 5) أضف المتغيرات السرية
من Render: Settings ثم Environment Variables.

أضف OPENAI_API_KEY = مفتاح OpenAI.
أضف BRAIN_ACCESS_TOKEN = مفتاح الدخول العشوائي.
اختياريًا أضف YOUTUBE_API_KEY للبحث المنظم في بيانات YouTube.
اختياريًا أضف GEMINI_API_KEY لتوليد الفيديو عبر Veo.

لا تضع أي واحد من مفاتيح API داخل HTML أو GitHub.

## 6) افتح الموقع من الآيفون
افتح رابط Render في Safari.
الصق BRAIN_ACCESS_TOKEN في خانة مفتاح الدخول واضغط حفظ المفتاح.
اضغط STATUS. يجب أن ترى API و Auth و OpenAI بعلامة ✓.

## 7) أول تجربة لصناعة البرومبتات
اكتب في الرسالة:
أريد فيديو 60 ثانية عن الطماطم من البذرة إلى الحصاد. بدون تعليق صوتي. عالمي، سينمائي، واقعي جدًا، وكل لقطة قابلة للتوليد بالـAI. ابحث أولًا عن الأنماط الحديثة في هذا النوع ثم ابنِ لي Production Pack كامل.

اختر BUILD ثم RUN BRAIN.

سيعمل النظام بالترتيب: بحث ثم استراتيجية ثم Prompt Pack ثم Critic ثم Repair.

## 8) عندما لا توجد فكرة
اكتب:
ما عندي فكرة. ابحث في النيش عن أفكار حديثة وبصرية قابلة للانتشار، وتجنب نسخ أي فيديو بعينه. أعطني فكرة واحدة فقط مع Production Pack جاهز.

أو اترك AUTO وسيتعرف النظام على عبارة ما عندي فكرة.

## 9) عندما تريد إعطاءه صورة
اختر صورة من الآيفون. الواجهة تضغط الصورة في المتصفح قبل إرسالها لتقليل حجم الطلب. اكتب مثلًا:
هذه الصورة مرجع بصري. أبقِ الإحساس العام للإضاءة والتركيب، لكن غيّر الموضوع إلى شتلة طماطم داخل التربة، وصمّم تحولًا زمنيًا سينمائيًا.

## 10) توليد أول لقطة
بعد نجاح RUN BRAIN سيظهر زر ولّد أول لقطة. إذا كان GEMINI_API_KEY مضبوطًا، سيرسل أول Shot Prompt إلى Veo 3.1 ويعيد ملف MP4 قابلًا للمشاهدة من الهاتف.

Veo 3.1 حاليًا يدعم 4 أو 6 أو 8 ثوانٍ و16:9 أو 9:16، ويدعم صورًا مرجعية وإطارات بداية/نهاية في سيناريوهات مدعومة. 

## 11) لماذا لا يكون الفيديو 60 ثانية بضغطة واحدة حتى الآن؟
لأن العقل يقسم الفيديو الطويل إلى عدة Shots قصيرة. النسخة الحالية تستطيع توليد لقطات متتابعة لكنها لا تملك بعد طبقة تجميع نهائي دائمة مع Queue وCloud Storage. هذه هي المرحلة التالية.

## 12) بحث YouTube
عند إضافة YOUTUBE_API_KEY يستطيع النظام استخدام search.list ثم videos.list لجمع العنوان والقناة والتاريخ والإحصاءات. YouTube تفرض حصصًا على البحث، لذلك صُممت النسخة الحالية بحيث لا تفرط في طلبات البحث.

  ## 13) النماذج الموجودة
gpt-6-luna: البحث والاستخراج والمهام المتكررة منخفضة التكلفة.
gpt-6.1-sol: الاستراتيجية والنقد والإصلاح عندما نريد توازنًا جيدًا بين الجودة والتكلفة.
gpt-6-astra: وضع القوة القصوى للمهام الأكثر تعقيدًا ويمكن تفعيله من Environment Variables.

## 14) شكل العقل
Model + Web Search + YouTube Data + Memory + Structured Output + Critic + Repair + Video Adapter.

## 15) ملاحظة مهمة جدًا عن Render Free
SQLite وملفات MP4 في القرص المحلي ليست تخزينًا دائمًا على Render Free. قبل أن تصبح الذاكرة والمخرجات جزءًا أساسيًا من القناة، سننقل الذاكرة إلى قاعدة خارجية ونقل الفيديو إلى Object Storage. Render يذكر صراحة أن الملفات المحلية تضيع عند restart/redeploy/spin-down على Free.
